## Context & Problem Statement

During live E2E testing of the HaqCheck web application (`https://main.duuh4vgnn5xa3.amplifyapp.com/`), selecting non-English languages (**Hindi** or **Kannada**) resulted in an English fallback text instead of grounded multilingual explanations generated by Bedrock Nova Lite.

Investigation identified two separate root causes:
1. **Application Guardrail Defect:** The `digits_ok()` guardrail in `backend/src/haqcheck/explain.py` used `re.findall(r"[0-9]+")`, which only matched ASCII digits. Kannada script numerals (೦–೯) were not handled, and any bullet numbering generated by the LLM (e.g., `1.`, `2.`) triggered a false-positive rejection, falling back to English.
2. **AWS Bedrock Account Verification Block:** All calls to `apac.amazon.nova-lite-v1:0` and other foundation models failed with `ValidationException: Operation not allowed` and `authorizationStatus: "NOT_AUTHORIZED"`.

## Engineering Steps Completed

### 1. Guardrail Patch on Branch `fix-multilingual`
- Created dedicated git branch `fix-multilingual`.
- Refactored `digits_ok()` in `backend/src/haqcheck/explain.py` to:
  - Match all Unicode digit categories (`\d+`).
  - Normalize Devanagari numerals.
  - Allow list numbering (single digits `1`–`9`) so list formatting does not trigger a false-positive rejection.
  - Added CloudWatch debug logging to log exact model output when guardrail rejections occur.
